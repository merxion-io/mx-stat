# hstat — монитор системы и AI-агентов Claude Code (MERXION)

Полноэкранный live-монитор в терминале (Textual, тема tokyo-night) с белым логотипом
MERXION в шапке. Кроме обычного «htop» показывает **живые сессии Claude Code**: что за
задача, какая модель, сколько контекста съедено, когда сессия последний раз писала,
сколько токенов за день, пульс ответов по минутам и гистограмма по часам.

```
█▀▄▀█ █▀▀ █▀█ ▀▄▀ █ █▀█ █▄ █  │ MacBook Pro · Apple M1 · macOS 26.5 · ↑ 9д 21ч · Tue 08.09  11:42:21
█ ▀ █ ██▄ █▀▄ ▄▀▄ █ █▄█ █ ▀█  │ CPU 24.3%  RAM 68%  load 2.49  ↓ 10 KB/с  ↑ 220 KB/с  🤖 5 busy 3 · 1с
```

## Установка

```sh
unzip hstat-merxion-*.zip && cd hstat-merxion
./install.sh
hstat            # TUI
hstat -s         # статичный снимок (для пайпов / скриншотов)
```

`install.sh` кладёт код в `~/.local/share/hstat`, создаёт там изолированный venv
(через `uv`, если он есть, иначе `python3 -m venv`) и пишет лаунчер `~/.local/bin/hstat`.
Нужен Python 3.11+. Пути переопределяются переменными `HSTAT_HOME` и `HSTAT_BIN`.

Проверка без терминала (headless, прощёлкивает все вкладки):

```sh
~/.local/share/hstat/venv/bin/python tests/smoke_test.py 140 46 --show
```

## Откуда берутся данные об агентах

Всё читается из файлов Claude Code, без API и без сети:

- **`~/.claude/sessions/<pid>.json`** — живые сессии: `sessionId`, `cwd`, `name`, `status`
  (`idle`/`busy`/`shell`), `version`, `startedAt`, `entrypoint` (`cli` / `sdk-cli`).
  Процесс проверяется через psutil: у Claude Code имя процесса — номер версии (`2.1.263`),
  надёжный признак — путь `exe` внутри `~/.local/share/claude/versions/`.
- **Транскрипт** `~/.claude/projects/<cwd с / и . → ->/<sessionId>.jsonl`:
  - `{"type":"ai-title","aiTitle":…}` — название задачи (колонка ЗАДАЧА);
  - `{"type":"last-prompt","lastPrompt":…}` — последний запрос пользователя;
  - строки `"role":"assistant"` с `"usage":` — токены, модель, `effort`; контекст =
    `input + cache_read + cache_creation` последнего ответа; метка `[1m]` в начале файла =
    лимит 1M, иначе 200K;
  - `gitBranch`, `permissionMode`, `entrypoint` — на строках user/assistant;
  - человеческий промпт = `"type":"user"` + `"origin":{"kind":"human"}`.
  Транскрипты читаются **инкрементально** (`SessionTracker` в `core.py`): с последнего
  смещения, поэтому многомегабайтные сессии не нагружают систему. Время в файлах UTC,
  срезы по часам/минутам переводятся в локальное.
- Статистика за день и за 7 дней — regex-скан всех `*.jsonl` с mtime за последние 36 ч / 8 дней,
  раз в 20 с в фоновом потоке.

## Особенности macOS, на которых всё держится

- `psutil.net_io_counters()` на macOS занижает трафик в сотни раз → счётчики из `netstat -ib`;
  в его выводе колонка Address есть не у всех интерфейсов, поля берутся **с конца** строки.
- `/` — read-only снапшот; реальная заполненность диска на `/System/Volumes/Data`.
- Температура CPU без sudo недоступна; показывается температура батареи из `ioreg -rn AppleSmartBattery`
  (там же циклы и здоровье).
- P/E-ядра: `sysctl hw.perflevel0.logicalcpu`. На Intel-маках разделения нет, подписи условные.
- `psutil.cpu_times_percent(percpu=True)` отдаёт проценты, не суммирующиеся в 100 — нормализуются.
- Статус `running` у psutil стоит у половины процессов, `cpu_stats().ctx_switches` почти не растёт —
  эти цифры не показываются.
- `lsof` режет имена процессов до 9 символов — имя и скрипт берутся через `psutil.Process(pid)`.
- Контейнеры — через `orb status` + `docker ps` (OrbStack); без OrbStack карточка просто пустая.

Написано и проверено на macOS (Apple Silicon). На Linux не тестировалось: часть команд
(`sysctl`, `netstat -ib`, `ioreg`, `scutil`) там отсутствует и соответствующие блоки будут пустыми.
